# Live CLI UAT — 2026-09-20

Sanitized user-acceptance run of the public `gr` command surface against a
saved Goodreads session. This is observation, not a compatibility promise.
It does not contain titles, authors, book IDs, owner ISBNs, review text,
profile paths, cookies, or CSV row contents.

Related evidence: [compatibility-matrix.md](compatibility-matrix.md).

## Setup

| Item | Value |
|---|---|
| Date | 2026-09-20 |
| Binary | local `gr dev` from `main` |
| Platform | Linux x86-64 |
| Browser | Google Chrome 143.0.7499.40 |
| Session | existing dedicated profile; `gr login` not run |
| Explicitly skipped | `gr logout`; headed troubleshooting windows |

The owner library had three rows: two exact-ISBN editions and one owner row
that renders neither ISBN-10 nor ISBN-13. `currently-reading` was empty.
A previously absent spec-example edition (`9781603580557`) was added for
compound mutations and removed afterward through the liveprobe restore path.

## Verdict

Reads, add, start, rate, review, export, MCP, validation, locking, and debug
redaction worked on this machine. Finish-date editing through the public CLI
did not on this run: a requested date other than today failed verification,
and restoring `read` after `start` stamped today then failed to clear it.
Those two items were later fixed; see [Follow-up](#follow-up).

## Passed

### Usage and validation

Local argument checks (no browser) accepted help, `--version`, and shell
completion. Invalid usage returned exit 2 with empty stdout, including:

- extra positional arguments on no-arg commands
- negative `--timeout`
- unknown flags
- invalid shelves, ratings, limits, and dates (including `2026-02-29` and
  unpadded `2026-9-17`)
- invalid or checksum-failing ISBNs, titles used as ISBNs, empty ISBN
- `review` without exactly one of `--text` / `--file` / `--clear`; empty or
  whitespace `--text`; missing `--file`; combining those flags
- `export --json` without `--out`; `--force` without `--out`; existing file
  without `--force`; directory, symlink, and missing-parent destinations
- `mcp` with extra arguments

`--json` on failures stayed on stderr as human text, matching the v0.1.1
decision that a JSON error envelope is out of scope.

### Authentication and process behavior

- `gr status` and `gr status --json` reported connected / `session_valid`.
- Persistent flags worked before or after the subcommand (`gr --json status`).
- `--no-color` was accepted.
- `GOODREADS_CLI_BROWSER` pointing at a missing executable returned exit 9;
  a later default `status` still used the saved session.
- Overlapping `library` and `status --timeout 400ms` returned exit 8 (`busy`);
  the first command still completed.
- `--debug` on successful live commands emitted only operation, stage, elapsed
  time, browser product/version, `error_kind`, and retry count.

`gr login` was not exercised. The saved session remained valid at the end of
the run.

### Library and get

- Unfiltered `library` returned the three owner rows as compact JSON and as
  human `Title — Author (status)` lines.
- `--shelf to-read`, `--shelf read`, `--rating 5`, `--rating 4` (empty),
  `--shelf read --rating 5`, `--limit 1`, and empty human `No books found`
  behaved as specified. Empty JSON shelves were `[]`.
- `get` accepted ISBN-13, ISBN-10, hyphenated, and spaced forms of a present
  exact edition.
- A valid ISBN not in the library returned exit 4.
- `get` / `library` omit `review` because they parse the shelf table.

All successful mutations below returned `verified: true` and left stderr empty
in JSON mode.

### Export

- `export --json --out` completed in a few seconds with metadata only
  (`ok`, path, byte count). CSV was not written to stdout.
- Destination already exists without `--force`: exit 2, no browser work.
- `--force` replacement and human-mode stdout CSV both succeeded.
- Header included `Book Id` and `Title`; row count matched the owner library

### MCP stdio

- Protocol `2025-03-26`; server name `goodreads-cli`, version `dev`.
- Tools: `get_library`, `get_book`, `add_book`, `start_reading`,
  `finish_reading`, `rate_book`, `review_book`. No `login` or `export`.

## Failed or flaky

### Finish date other than today — done

`finish --date` on a day that was not the machine-local calendar date returned
exit 5. When the book had just moved to `read`, the error was typed
`partial_mutation` (`completed: status`, `failed: date`, observed date today,
`retry_automatically` false, rating not applied). When status was already
`read`, the same date change returned generic `verification_failed` with debug
`stage=unknown`, because no earlier step was recorded as completed.

`finish` succeeded when the requested date was already today.

Later liveprobe: the session start date was blocking the earlier finish date.
Moving that start date first, then setting the end date, verified a requested
day other than today.

### Restoring `read` after `start` — done

Public `add --shelf read` after `start` on an edition whose finish date was
unset returned exit 5 `partial_mutation`: status became `read`, Goodreads
stamped today, and clearing that date failed. A later owner-shelf read still
showed today's date. The matching Goodreads CSV `Date Read` cell for that row
was blank. There is no public command to clear a finish date.

The liveprobe status canary still documents that a transition to `read` creates
a finish date and that restoration is possible through probe-only date
clearing. The public CLI path did not restore the original unset date.

Later liveprobe: blanking the date dropdowns did not persist. Removing the
dated reading session does, after ensuring another session row remains. The
residual UAT finish date was restored to unset.

### `review --file` trailing newline — done

A review file whose exact bytes ended in `\n` returned exit 5 after readback.
The same text without the trailing newline verified. Ordinary editor-saved
files include that newline.

Later: `--file` strips one trailing newline (`\n` or `\r\n`) before the review
is sent, and keeps an extra blank line when the file ends with two newlines.

### Empty `currently-reading` timeout — done

The empty exclusive shelf is usually `[]` in about four seconds. In this run
it also hit the one-minute default timeout twice: first CLI
`library --shelf currently-reading --json` (exit 6) and MCP `get_library` for
that shelf (`code: timeout`). Retries succeeded. Treat empty
`currently-reading` as flaky under the default timeout.

Later: `NewPage` waits for a real document body instead of `window.onload`, so a
hanging image or unfinished HTML stream cannot consume the library deadline.
Library reads also parse the requested shelf directly instead of first loading
the unfiltered library. A local Chromium fixture with a never-completing image
still returned an empty exclusive shelf. Three live
`library --shelf currently-reading --json` retries on this session returned `[]`
in about two seconds.

### Public ISBN of an owner row that does not render ISBN — done

`get` of a present exact ISBN still works. `get` of a real absent ISBN still
returns exit 4. `get` of a plausible public ISBN for the unidentified owner
row returned exit 7 (`compatibility`) after about 181 seconds, debug
`stage=library.row`. The public-ISBN identity fallback did not complete
cleanly for that input.

Later: public identity no longer waits for the Want-to-Read add control,
keeps lookup timeouts as timeouts, and matches the already-scanned owner
rows instead of loading the library again. A local owned-book-page fixture
without Want to Read resolved the unidentified row by public book ID. A
live retry of the same public ISBN returned exit 4 (`book_not_found`) in
about 27 seconds: the proved public edition was not the unidentified owner
row.

### Unknown command — done

`gr foobar` and `gr --debug foobar` returned exit 1 and
`Goodreads operation failed.` instead of exit 2 usage text.

Later: unknown commands are classified as the same usage sentinel as invalid
flags. `gr foobar`, `gr --debug foobar`, and `gr --json foobar` now return
exit 2 with `unknown command "foobar"` on stderr and empty stdout. `--debug`
reports `error_kind=invalid_arguments` and `exit_code=2`.

### Tiny `--timeout` — done

`status --timeout 1ms` returned exit 9 (browser unavailable) rather than
exit 6 (timeout). Browser discovery lost the race with the deadline.

Later: an already-expired operation context stays a timeout or cancellation
during profile lock, executable discovery, and launch. `--version` probe
failures are not wrapped as unavailable once the command deadline has fired.
A hanging local Chrome fixture with a 40ms deadline returns
`context.DeadlineExceeded` rather than `browser_unavailable`. Three live
`status --timeout 1ms --json --debug` retries on this session returned exit 6
with `error_kind=timeout` and empty stdout. A missing browser with a live
deadline is still exit 9.

### Default `rate` timeout

The first two public `rate` calls hit the 60-second command default (exit 6)
and did not change the rating. The same operations with `--timeout 3m`
completed in about 19 seconds.

## Account state after the run

Session remained connected. `logout` was not invoked.

The throwaway spec-example edition was absent again. The two exact-ISBN owner
rows were restored except for the residual CLI finish date on the edition that
went `read` → `currently-reading` → `read` through public `add`. That leftover
date was cleared in the later liveprobe. The unidentified-ISBN owner row was
not mutated.

## Not covered

- fresh interactive `gr login`
- `gr logout` (forbidden for this run)
- `--headed`
- macOS / Windows
- Rod-managed Chromium download
- a library larger than one shelf page
- MCP `add_book` / `start_reading` / `finish_reading` / `review_book` writes

## Follow-up

The two finish-date failures above are done. A later liveprobe on this same
session set a finish date other than today, verified it from the shelf, and
restored the leftover unset dates. Public `gr finish --date` was not re-run;
it uses the same adapter path. The `--file` trailing-newline failure is also
done: ordinary editor-saved files now drop one file terminator before
verification. Empty `currently-reading` timeouts are done: navigation no longer
waits for `window.onload`, and library reads go straight to the requested shelf.
Public-ISBN fallback for an unidentified owner row is done: identity proof
uses book-page metadata rather than Want to Read, and a live retry of the
same public ISBN completed as `book_not_found` instead of hanging into
`library.row`. Unknown commands are done: they are usage errors (exit 2)
instead of an internal failure. Tiny `--timeout` is done: a 1ms deadline
during browser discovery stays a timeout (exit 6) instead of browser
unavailable (exit 9). See [compatibility-matrix.md](compatibility-matrix.md).
