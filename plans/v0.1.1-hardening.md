# v0.1.1 hardening plan

Status: In progress
Target: v0.1.1  
Depends on: v0.1.0 (`874537c`)

This is an execution plan. The normative behavior lives in [`../specs/`](../specs/README.md); if this plan and a specification disagree, the specification wins.

## Goals

- Exact-ISBN operations work for libraries beyond the current ten-page scan bound.
- Compound mutations report verified partial progress and reconciled safe state.
- Browser integration runs in ordinary continuous integration rather than only manual release preparation.
- Network and compatibility failures produce useful redacted diagnostics.

## Non-goals

- remote HTTP MCP or hosted deployment;
- local library storage, caching, a sync ledger, or a mutation queue;
- title/fuzzy search, recommendations, or public book discovery;
- new Goodreads mutation commands;
- automatic mutation rollback or replay;
- installation/package-manager work or `gr doctor` (deferred to v0.2).

## Delivery rules

- Implement one vertical slice at a time and keep `main` releasable.
- Add failing tests before changing behavior where practical.
- Do not run live Goodreads mutations from ordinary CI.
- Update the compatibility matrix only with observed evidence.
- Do not weaken exact identity or preservation checks to make a test pass.

## Slice 1 — scalable exact-edition resolution

### Problem

`get` and mutation candidate lookup currently scan at most ten shelf pages. Exact lookup can therefore fail for a library that has more pages even when the target is present. An unidentified row also blocks `get` from proving uniqueness.

### Compatibility experiment

Using a dedicated/non-critical account and redacted observations:

1. test the visible owner-library search/filter UI with exact ISBN-10 and ISBN-13;
2. determine whether it proves the exact owner row and preserves authenticated page identity;
3. test exact public ISBN resolution to stable Goodreads book ID, then locating that ID in the owner library;
4. if neither targeted path is sufficient, establish the largest proven `per_page` value and reliable termination markers;
5. record request counts, pagination behavior, unidentified rows, absent books, duplicates, and loops.

### Implementation contract

- Introduce one semantic exact-edition resolver shared by `get`, `add`, `start`, `finish`, `rate`, and `review`.
- Prefer the smallest tested visible-UI path that proves exact identity.
- Keep visited-page loop detection and operation-context cancellation.
- Separate list-result limits from exact-resolution safety budgets.
- Return `ErrScanIncomplete` when a safety budget ends an otherwise valid scan.
- Guarantee that no mutation occurs after `ErrScanIncomplete`.
- Do not use a private API, CSV snapshot, local index, or fuzzy title match.

### Tests

- target on the first page of a library larger than ten pages;
- target beyond page ten;
- absent target after actual termination;
- exact ISBN-10 and ISBN-13;
- duplicate exact candidates;
- unidentified owner row;
- pagination loop or repeated next link;
- safety-budget exhaustion;
- validation that mutation controls are never invoked after incomplete resolution.

### Acceptance criteria

- A synthetic library exceeding ten pages resolves a present exact edition.
- True absence is returned only after conclusive termination.
- Budget exhaustion has a distinct safe error in application, CLI, and MCP layers.
- The compatibility matrix records the selected Goodreads path and live evidence.

## Slice 2 — compound mutation reconciliation

### Problem

`finish` performs status, date, and optional rating writes. `add` may add to `to-read` and then change status. A later failure can leave earlier verified changes in Goodreads while the command returns an error without describing the current state.

### Application model

Add a typed `PartialMutationError` containing:

- semantic operation;
- ordered completed steps;
- failed step;
- safe observed state after one final readback;
- `retry_automatically=false`.

Safe observed fields are exclusive status, numeric rating, and ISO date. Review text, book/title/account identifiers, selectors, raw URLs, HTML, and profile paths are prohibited.

### Execution contract

- Verify each semantic write before starting the next.
- Track completed steps only after verification.
- On later failure, attempt exactly one safe final readback.
- Return `ErrPartialMutation` when at least one step is verified and final safe state is available.
- Return `ErrMutationAmbiguous` if final state cannot be established.
- Never automatically roll back or replay a write.
- Preserve existing idempotent behavior on a later user-initiated invocation.

### Tests

Inject failure:

- after `add` succeeds but before status change;
- after finish status succeeds but before date save;
- after date succeeds but before optional rating;
- during final reconciliation readback;
- when no write occurred;
- when every step succeeds.

Assert CLI exit code 5, MCP structured error data, redaction, step ordering, and no automatic retry.

### Acceptance criteria

- Every compound failure path reports either verified partial state or explicit ambiguity.
- No error claims that Goodreads is unchanged after a verified earlier step.
- Public errors contain no private review or identity data.

## Slice 3 — continuous integration and real browser flows

### Workflow

Add a normal CI workflow for pull requests and pushes to `main`:

1. formatting check;
2. `go vet ./...`;
3. `go test ./...`;
4. `go test -race ./...` on Linux;
5. compile for Linux, macOS, and Windows targets;
6. Linux/Chrome component job with `GOODREADS_BROWSER_TESTS=1`.

Refactor the release workflow to depend on or repeat the same required checks before GoReleaser publishes. Live Goodreads tests remain manual and require an already prepared dedicated account/profile.

### Synthetic browser flows

At least one local test must execute the real Rod wrapper and production Goodreads page contracts together for:

- authenticated paginated library read;
- exact-edition resolution;
- rating mutation plus fresh readback;
- ambiguous post-click outcome;
- compound-operation partial failure.

### Acceptance criteria

- Pull requests and `main` receive required CI status before release tagging.
- The browser job fails on production selector/wait integration regressions.
- CI never contacts Goodreads or requires credentials.

## Slice 4 — diagnostics and network errors

### Error taxonomy

- Implement and consistently map `ErrNetwork`.
- Implement `ErrScanIncomplete` and `ErrPartialMutation`.
- Preserve exit code 5 for partial, ambiguous, and verification failures.
- Use exit code 6 for network/remote failures and incomplete bounded scans.
- Map the same kinds into MCP tool errors.

### Redacted debug events

With `--debug`, emit to stderr:

- operation;
- stable flow stage;
- elapsed duration;
- browser product/version;
- typed error category;
- retry count when non-mutating retries occur.

Do not emit selectors, authenticated URLs, ISBN/book/title/author values, review text, raw HTML, cookies, browser storage, form values, export contents, or profile paths.

### Acceptance criteria

- Representative browser/network failures map to stable public kinds and exit codes.
- Debug output is materially more useful than ordinary output and remains safe to paste into an issue.
- CLI and MCP tests assert redaction of private and identity fields.

## Release gate

Before tagging v0.1.1:

- all ordinary tests, race tests, vet, formatting, and target builds pass;
- the Linux/Chrome component job passes in CI;
- large synthetic libraries and incomplete scans pass their acceptance tests;
- failure after every compound mutation step is covered;
- one manual fresh `gr login` smoke test succeeds on the release browser matrix;
- live exact-resolution and compound-operation evidence is recorded without private data;
- README limitations and compatibility matrix match observed behavior;
- release artifacts and checksums are produced without changing the Goodreads-only architecture.
